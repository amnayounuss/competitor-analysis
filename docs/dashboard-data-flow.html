Dashboard Data Flow

How data is scraped, computed, stored, and displayed
Anoosh SaaS — Multi-Tenant Google Reviews Competitor Analysis Platform
Generated: May 2026

1. Pipeline Overview

Data flows through 6 stages from Google Maps to the dashboard. Each stage transforms and enriches the data before passing it forward.

1
Scraping
target-fetcher.js · scraper.js · hours-scraper.js · popular-times.js
Collects raw branch data, reviews, hours, and popular times from Google APIs and Google Maps via Puppeteer.
2
Analysis
analyzer.js
Pure computation — takes raw places, filters reviews by date window, computes per-branch metrics and per-brand aggregates.
3
File Generation
excel-builder.js · report-builder.js
Produces the 6-sheet Excel workbook and Markdown analytical report.
4
Database Insert
job-runner.ts → pushDataToClientDb()
Inserts branches, reviews, analyses, and branch_analytics into the client's Supabase database.
5
Dashboard Query
app/dashboard/page.tsx
Server component fetches the latest succeeded job's branch_analytics and analyses from the client DB.
6
Dashboard Render
app/dashboard/dashboard-view.tsx
Client component aggregates branch_analytics rows into brand summaries, computes chart data, and renders SVG charts.

2. Stage 1 — Scraping (Raw Data Collection)

2.1 Target Brand (Google Business Profile API)

File: scrapers/target-fetcher.js

Uses the client's OAuth refresh token to call Google's Business Profile API. For each location found:

{
  title:           "Anoosh - Riyadh Park",
  address:         "Riyadh Park Mall, Floor 1, Riyadh 12345, SA",
  phone:           "+966 11 234 5678",
  placeId:         "ChIJ...",
  url:             "https://google.com/maps/place/?q=place_id:ChIJ...",
  reviews: [
    { stars: 5, publishedAtDate: "2026-03-15T...", text: "Amazing service" },
    { stars: 3, publishedAtDate: "2026-02-20T...", text: "Too crowded" },
    ...
  ],
  __searchBrand:   "Anoosh"     // ← from config.targetName
}

2.2 Competitors (Puppeteer Scraping)

File: scrapers/scraper.js

Opens Google Maps search URLs (e.g. google.com/maps/search/Patchi+Saudi+Arabia), scrolls the results feed to discover branch URLs, then visits each branch page to extract:

  • Address, hours, phone — from the place details panel
  • Rating & review count — Google's displayed values (e.g. 4.3 stars, 1,234 reviews)
  • Individual reviews — from the Reviews tab, sorted newest-first. Relative dates like "2 months ago" are converted to ISO dates.

Each branch is tagged with __searchBrand matching the competitor name from the job config.

2.3 Brand Matching Logic

Priority order:

1. __searchBrand (set by scraper) — always trusted
2. Keyword match against BRAND_KEYWORDS (target first, then competitors)
3. Fallback: "Other"

When Google Maps returns titles in Arabic or non-Latin scripts, the keyword match may fail. In this case, ALL results from a brand-specific search URL are accepted and tagged with that brand name (since the search query was already brand-specific).

3. Stage 2 — Analysis (Computation)

File: scrapers/analyzer.js → analyze(rawPlaces)

3.1 Date Window

if (config.DATE_START && config.DATE_END) {
  window = [DATE_START 00:00:00, DATE_END 23:59:59]
} else {
  window = [today - LOOKBACK_MONTHS, today]
}

Only reviews with publishedAtDate inside this window are counted.

3.2 Per-Branch Metrics

Function: computeBranchMetrics(place, cutoffDate, endDate)

FieldCalculation
avgRating3mSimple average of all review stars in window: Σstars / count
totalReviews3mCount of reviews where cutoff ≤ date ≤ endDate
stars5..stars1Histogram: count of reviews with each star rating (rounded)
month1CountReviews in newest third of window (0–33% from end)
month1AvgAverage stars for month 1 reviews only
month2Count/AvgReviews in middle third (33–67%)
month3Count/AvgReviews in oldest third (67–100%)

Window Division: The window is split into 3 equal time segments, NOT fixed 30-day periods. For a 90-day window, each "month" is 30 days. For a 6-month window, each is ~60 days.

3.3 Per-Brand Aggregates

Function: computeBrandSummary(branchRows)

For each brand:
  totalBranches  = count of branches with this brand
  totalReviews3m = SUM(branch.totalReviews3m)
  avgRating3m    = SUM(branch.avgRating3m × branch.totalReviews3m)
                 / SUM(branch.totalReviews3m)

Key formula — Weighted Average Rating:
avgRating = Σ(branch_avg × branch_reviews) / Σ(branch_reviews)

This prevents a branch with 1 review (5☆) from distorting the brand mean vs a branch with 500 reviews (4.2☆). This formula is used consistently in the analyzer, database insert, AND dashboard rendering.

5. Stage 4 — Dashboard Query & Rendering

5.1 Server-Side Query

File: app/dashboard/page.tsx

// 1. Find latest succeeded job for the logged-in user
const latestJob = await admin.from('jobs')
  .select('id, target_name, competitors, date_start, date_end, ...')
  .eq('user_id', user.id)
  .eq('status', 'succeeded')
  .order('finished_at', { ascending: false })
  .limit(1);

// 2. Fetch all analytics + analyses for that job
const analytics  = await cdb.from('branch_analytics').select('*').eq('job_id', jobId);
const analyses   = await cdb.from('analyses').select('*').eq('job_id', jobId);

5.2 Client-Side Aggregation

File: app/dashboard/dashboard-view.tsx → buildBrandSummaries()

Re-aggregates branch_analytics rows into brand-level summaries:

For each brand (grouped from branch_analytics rows):
  branches     = COUNT(rows)
  totalReviews = SUM(total_reviews_period)
  avgRating    = SUM(avg_rating_period × total_reviews_period)
               / SUM(total_reviews_period)                  // weighted avg
  stars[5..1]  = SUM(star_5_count), SUM(star_4_count), ...
  monthly[0]   = {
    reviews: SUM(month_1_reviews),
    avg:     SUM(month_1_avg_rating × month_1_reviews)
           / SUM(month_1_reviews)                           // weighted avg
  }
  // same for monthly[1] (month_2) and monthly[2] (month_3)

Every chart in the dashboard is rendered as pure SVG (zero external libraries). Below is what each chart shows and exactly how its data is derived.

7. Key Formula Used Everywhere

Weighted Average Rating

avgRating = Σ(branchi.avg × branchi.reviews) ÷ Σ(branchi.reviews)

This formula is consistent across all 3 layers:

• analyzer.js → computeBrandSummary()
• job-runner.ts → pushDataToClientDb() (stored in analyses.avg_rating_3m)
• dashboard-view.tsx → buildBrandSummaries()

Why weighted? A branch with 1 review at 5☆ should not outweigh a branch with 500 reviews at 4.2☆. Weighting by review count ensures the brand average reflects actual customer volume.
